## Модели и данные

Meaningfulness использует хешированные символьные n-граммы длины 2–4 и восемь статистических признаков, включая длину, долю цифр и разнообразие символов. Сравнили Logistic Regression и Linear SVM. Для исполнения экспортированы 4 104 коэффициента и один intercept. Для коротких корректных терминов применяется отдельное правило политики. Оно оставляет сырой диагностический балл модели доступным в CLI.

Relevance использует семь признаков, отражающих совпадение слов, косинус разреженных векторов понятий и покрытие выбранного курса. Логистическая регрессия обучает семь коэффициентов и intercept. Новому курсу можно передать описание или добавить терминологию в каталог без изменения размерности признаков. При неизвестном курсе с недостаточной связью между заголовком и описанием система просит уточнение.

Обе логистические модели минимизируют взвешенную log loss с L2-регуляризацией с помощью L-BFGS. Баллы получаются сигмоидой от линейной комбинации признаков. Они не прошли внешнюю калибровку. Пороги подобраны по F1 на validation. Каталог понятий фиксирован, обучаемых параметров кодировщика нет.

Рассмотрены multilingual E5-small и multilingual MiniLM. E5 кодирует текст в плотный вектор и рекомендует префиксы для входов; MiniLM предоставляет многоязычные векторы для сходства предложений. Для обоих вариантов понадобились бы отдельные веса и измерение CPU/RAM, в том числе для INT8 ONNX. В этом цикле веса не скачивались и эксперименты с предобученными энкодерами и CNN не проводились. Реализован компактный вариант на существующей зависимости NumPy. [E5 model card](https://huggingface.co/intfloat/multilingual-e5-small), [MiniLM model card](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).

Генератор с seed 13 создал 3 448 заголовков и 10 344 пары курс–заголовок. Один заголовок оценивается для всех трёх курсов. Разделение по группам тем и вариантам заголовка дало 2 327 / 499 / 622 заголовков и 6 981 / 1 497 / 1 866 пар в train / validation / test. Синтетические шаблоны повторяются между группами, а темы теста доступны в фиксированном каталоге. Язык размечен по шаблону, поэтому часть названий содержит иноязычные термины. Результаты не дают оценки качества на новых специализациях или реальных пользовательских названиях.

## Интеграция и измерения

Новые проверки включаются настройкой `MATERIAL_VALIDATOR_V2_ENABLED=true` и по умолчанию выключены. Проверка выполняется до записи PDF в storage, вставки материала и начисления XP. Публичные ошибки используют 422 для отклонённого заголовка и 503 для недоступной модели. В ответ API попадает пользовательское сообщение. Модель загружается лениво и кэшируется в процессе.

Две модели в одном NPZ занимают 32 150 байт. В локальном Windows CLI полный путь Week 12 + V2 занял около 150 мс при первом вызове, 1,49 мс p50 и 2,58 мс p95 после прогрева. В прогоне на четырёх потоках все 200 решений совпали. Эти замеры не включают HTTP, БД и запуск приложения. В отдельном Windows-процессе с импортированным FastAPI-приложением рабочий набор составил 110,3 МиБ после импорта, 115,7 МиБ после загрузки Week 12 и 116,0 МиБ после первого вызова V2. После 200 проверок он остался около 116,0 МиБ, общий пик процесса составил 143,1 МиБ. Измерение через GetProcessMemoryInfo выполнено без Uvicorn и HTTP-нагрузки. Linux и фактическая совместимость с Render Free не проверены. Production не развёртывался.

Запустить из корня проекта в Windows PowerShell с готовым виртуальным окружением проекта. Для обучения нужен scikit-learn 1.8.0. Для работы backend достаточно существующих зависимостей.


### Замороженный challenge и разработка

Набор содержит 300 пар для DB101, PROG101 и BIS101 из локального PostgreSQL. В нём 44 обычных релевантных названия, 60 перефразирований, 104 отрицательные пары с теми же названиями для другого курса, 12 заголовков с отвлекающим академическим термином, 24 внеучебных названия, 28 шумовых строк и 28 неоднозначных примеров. Неоднозначные случаи исключены из бинарных метрик. Все варианты языка и курсы одной смысловой группы помечены одним `base_id`. Примеры составлены ассистентом отдельно от Phase 1, без внешней проверки человеком. Разметка привязана к границам трёх учебных программ, поэтому часть тематических границ стоит дополнительно согласовать с преподавателем.

SHA-256 файла `ml_moderation/datasets/phase2_challenge.txt` с нормализованными переносами строк: `03974205471e2c169f52d3840056cbeb1a0256c1558de698bf924e74bb31454e`. Этот хеш проверяется перед экспериментом. Для обучения использовались 2 295 пар из групп исходного synthetic train с seed 13. Из отдельного `phase2_dev.txt` получены 72 пары для настройки. Код проверяет точные совпадения заголовков между тремя выборками. Перефразирования независимы по формулировке, хотя часть учебных тем и все три названия курсов намеренно повторяются. Регрессия с удержанием курса дополнительно исключает его пары из обучения и исключает родственные группы из dev. Эта проверка оценивает перенос классификатора на контекст без обучающих пар этого курса. Контекст курса при инференсе известен, и часть синтетических названий могла встречаться как нерелевантная для других курсов.

### Что обучалось

Обе модели используют замороженный 12-слойный BertModel, 12 голов внимания, скрытую размерность 384, FFN 1 536 и словарь из 250 037 токенов. Из конфигурации это 117 505 920 параметров на пути скрытых состояний без неиспользуемого pooler. Ни один параметр энкодера не обучался. Веса из опубликованных INT8 ONNX, с закреплёнными ревизиями и SHA-256. E5 имеет MIT, MiniLM — Apache-2.0. Авторы заявляют широкий многоязычный охват, а пригодность для казахского оценена отдельно на нашей выборке. E5 получает префиксы `query:` и `passage:`. Оба варианта используют mean pooling с attention mask, L2-нормировку и ограничение 128 токенов. [E5](https://huggingface.co/intfloat/multilingual-e5-small), [MiniLM](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).

Полный контекст содержит официальное название курса и его группы тем. Сравнение с отдельными темами использует максимум, среднее, второй максимум и разброс cosine. Ещё один признак — средняя абсолютная разность между векторами заголовка и полного контекста. Вместе с cosine полного контекста это 6 признаков. Семантическая Logistic Regression имеет 6 коэффициентов и bias, гибрид — 13 коэффициентов и bias, включая 7 признаков V2.0. Оба классификатора реально обучены с балансировкой классов, веса сохранены в отдельных NPZ. У cosine нет обучаемых коэффициентов. Каскад использует V2.0 при совпадении понятия и семантическую регрессию для остальных заголовков. Энкодер всё равно занимает RAM после первого вызова.

Порог принятия выбирался по Macro F1 на dev. Область уточнения определялась по 90-му процентилю отрицательных dev-баллов ниже порога. Выше порога — принять, в промежутке — уточнить, ниже — отклонить. Cosine — сходство направлений, его значение не интерпретируется как вероятность. Бинарная таблица измеряет принятие против всех остальных решений и отдельно показывает долю явных отказов на hard negatives. Для полной цепочки остаются действующими Week 12, проверка осмысленности и правила для общих заголовков.

### Данные и модель

К исходным 2 295 синтетическим парам добавлено 180 новых пар с отдельными формулировками EN, RU, KK и mixed. Dev из 72 пар использован для выбора варианта и порогов. Финальные 300 пар (84 положительные, 168 парных hard negatives, 24 других отрицательных и 24 неоднозначных) получены из 25 смысловых групп. В них ровно 60 незнакомых релевантных перефразирований. Проверено отсутствие точных совпадений заголовков между выборками. Групповые переводы и пары по курсам не разделялись. Исторический benchmark не участвовал в обучении и использовался как диагностический. Итоговый holdout имеет заранее записанный SHA-256 `7922a02dc0bc7c5b551ffaefdf9f36081c00320f2f57c36845ac5c75c17bf050`. Скрипт записывает выбор модели, пороги и хеш весов до чтения итоговых примеров. Разметка составлена ассистентом. В `human_label_review.csv` предусмотрены поля для проверки человеком.

Model2Vec заменяет последовательный прогон трансформера поиском заранее вычисленных векторов токенов и их агрегацией. Это сокращает вычисления, но размер словаря по-прежнему влияет на память. Рассмотрен MIT-вариант Potion multilingual 128M, созданный из BGE-M3, с 256-мерными векторами и заявленными 101 языками. Опубликованный файл весов занимает 512 МБ, токенизатор — 18,6 МБ. Его не скачивали и его RAM не измеряли. Выбран компактный статический ученик по тому же принципу, без зависимости Model2Vec в production. [Model2Vec](https://github.com/MinishLab/model2vec), [карточка Potion](https://huggingface.co/minishlab/potion-multilingual-128M), [размеры файлов Potion](https://huggingface.co/minishlab/potion-multilingual-128M/tree/main).

MiniLM INT8 выдаёт исходные 384-мерные векторы предложений. PCA, обученная на train, сокращает их до 64 координат. Ridge-регрессия учит 8 192 хешированных признака слов и символьных 3–4-грамм восстанавливать компактный вектор учителя. Это 524 288 коэффициентов, сохранённых как signed INT8 с 64 масштабами. В production таблица распаковывается в float32 один раз, а эмбеддинги контекстов и шести тем каждого курса предварительно вычислены. Unicode-фрагменты дают покрытие ранее не встреченных слов, но хеширование допускает коллизии и не заменяет большой словарь. Ни один параметр MiniLM не изменялся. Для релевантности дополнительно обучены LR на 5 семантических признаках и LR на 12 признаках с добавлением лексики. Soft-эксперимент использует 75% вклада истинной метки и 25% вклада сигнала учителя после нормирования на train. Soft score не считается вероятностью. Размер выбранного NPZ **370 815 байт**.

### Режимы и ресурсы

В V2.2 пороги разделяют принятие, явный отказ и неопределённость. Разница между курсами — входной признак, поэтому лучший результат другого курса сам по себе не блокирует материал. При включённом V2 и выборе `v2_2` режим `off` отключает новые проверки, `shadow` пишет код результата в журнал и сохраняет обычный HTTP-ответ, `enforce` отклоняет явные отказы, а неопределённые заголовки пропускает. Порогов, баллов и дополнительных полей в API нет. Week 12 выполняется первой во всех режимах. Проверка осмысленности Phase 1 продолжает предшествовать семантическому этапу. Настройка `enforce` предназначена для тестирования; запускать её на Render не рекомендовано.

Замер Windows с импортированным FastAPI и полной цепочкой Week 12 + V2.2: **122,8 МиБ** после загрузки, **153,0 МиБ** на пике старта и всего прогона. Средний CPU в одиночном прогоне — **1,07 эквивалента ядра**. Ученик использует NumPy из текущих требований. ONNX Runtime и MiniLM нужны только для обучения и экспериментов с учителем. Результаты сняты после импорта backend без HTTP и PostgreSQL в цикле измерения. Windows working set описывает физически резидентные страницы процесса; Linux RSS учитывает страницы по правилам Linux, а контейнерный cgroup может также учитывать файловые страницы и другие процессы.
